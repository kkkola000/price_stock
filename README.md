# Каталог товаров поставщиков

Веб-сервис для хостинга с Plesk: админ-панель для настройки источников данных
(прайсы Excel/CSV, YML-фиды — файлом или по ссылке) и публичная витрина
с объединённым каталогом, поиском, фильтрами и мобильной вёрсткой.

Без Composer и внешних библиотек — только PHP и MySQL, чтобы разворачивалось
на обычном шаред-хостинге.

---

## Возможности

**Админ-панель**

* Источники данных: Excel (.xlsx и .xls, включая Excel 97–2003), CSV/TXT, YML-фид (XML).
* Два способа получения файла: ручная загрузка и ссылка (скачивание по расписанию).
* Ссылки на **Google Таблицы**, **Google Диск**, **Яндекс Документы** и **Яндекс Диск**
  вставляются как есть — сервис сам получает прямую ссылку на файл.
* Гибкий маппинг:
  * для Excel/CSV — номер столбца (`1`, `2`) **или** буква (`A`, `B`, `AA`) для каждого поля;
  * для YML — названия тегов внутри `<offer>`, включая атрибуты (`@id`, `@available`).
* Все поля маппинга необязательные: заполняется только то, что есть в прайсе
  (название, артикул, цена, остаток, фото, валюта).
* Настройка разбора: сколько строк шапки пропустить, номер листа книги Excel,
  разделитель и кодировка CSV (или автоопределение).
* Галочка «Не импортировать скрытые строки и столбцы» — для поставщиков,
  которые прячут в книге неактуальные позиции.
* Своя валюта у каждого источника: код (`KZT`, `USD`) или собственное обозначение
  (`тг`, `сум`) — на случай, когда валюты нет в самом прайсе.
* Наличие сохраняется и показывается в том виде, как его передал поставщик.
* Запуск импорта вручную (по одному источнику или все сразу) и автоматически по расписанию.
* Проверка маппинга до импорта: видно, что прочитано из файла и что попадёт в каталог.
* Список источников: поставщик, тип, способ получения, дата последнего успешного импорта,
  статус (активен / ошибка / отключен), количество товаров.
* Источник можно отредактировать, **деактивировать** (товары скрываются с витрины, данные остаются)
  или удалить полностью.
* Журнал импортов: время, длительность, сколько прочитано / импортировано / пропущено / удалено, текст ошибки.

**Витрина**

* На компьютере — список с колонками: товар, артикул, наличие, цена, поставщик.
* На телефоне — карточки в одну колонку, фильтры шторкой снизу.
* Наличие показывается ровно так, как его передал поставщик: «7», «в наличии»,
  «под заказ», «мало» — без пересчёта в свои формулировки.
* Цена показывается так же дословно, как записана в прайсе; валюта дописывается,
  только если её нет в самой записи.
* Поиск по названию и артикулу с задержкой ввода (debounce 350 мс).
* Фильтр по поставщику — множественный выбор.
* Сортировка: по цене (по убыванию — по умолчанию, и по возрастанию), по названию, по дате обновления.
* Сброс всех фильтров одной кнопкой.
* Раздел «Заказы»: кнопка «+» у товара, списки по поставщикам, количество,
  выгрузка в файл и очистка.
* Кнопка «?» в шапке: окно со списком поставщиков и датой обновления их прайсов.
* Подгрузка по скроллу + кнопка «Показать ещё», состояние фильтров сохраняется в адресе страницы.
* Тема всегда светлая, независимо от настроек системы у посетителя.

## Требования

* PHP 8.1 или новее, расширения: `pdo_mysql`, `mbstring`, `zip`, `xml`/`xmlreader`, `curl`, `iconv`.
* MySQL 5.7+ / MariaDB 10.3+.
* Apache с `mod_rewrite` (стандартная конфигурация Plesk) — либо nginx, см. ниже.

> Форматы Excel читаются встроенным разбором: `.xlsx` (Excel 2007+) и `.xls` (Excel 97–2003).
> Composer и PhpSpreadsheet не нужны.

## Установка на Plesk

### Быстрый путь — одной командой по SSH

```bash
cd /var/www/vhosts/ВАШ_ДОМЕН
git clone https://github.com/kkkola000/seller_pack.git stocks
cd stocks
./deploy/install.sh
```

Скрипт сам найдёт подходящий PHP (в том числе сборки Plesk из `/opt/plesk/php/*`),
проверит расширения и права, спросит доступы к базе и логин администратора,
создаст `config.php` со случайным токеном для планировщика, применит схему БД,
выставит права и напечатает две оставшиеся настройки для панели Plesk —
путь для корня документов и готовую команду для запланированной задачи.

Без вопросов, все параметры сразу (удобно для повторного развёртывания):

```bash
DB_NAME=catalog_db DB_USER=catalog_user DB_PASS='пароль_базы' \
ADMIN_USER=admin ADMIN_PASS='пароль_админа' SITE_NAME='Каталог Anex' \
./deploy/install.sh
```

Доступные переменные: `DB_HOST` (по умолчанию `localhost`), `DB_PORT`, `DB_NAME`,
`DB_USER`, `DB_PASS`, `SITE_NAME`, `ADMIN_USER`, `ADMIN_PASS`, `PER_PAGE`,
`TIMEZONE`, `CRON_TOKEN`, `PHP_BIN` (путь к PHP, если автоопределение промахнулось).

Повторный запуск безопасен: существующий `config.php` и уже созданный
администратор не перезаписываются.

**Базу данных создайте заранее** в Plesk: **Базы данных → Добавить базу данных.**

### Остальные команды

```bash
./deploy/update.sh              # обновить: бэкап, git pull, схема и миграции, права
./deploy/update.sh --no-backup  # то же без резервной копии
./deploy/backup.sh              # дамп базы + архив прайсов в storage/backups (хранятся 7 последних)

php bin/setup.php --check       # диагностика: PHP, расширения, права, база, таблицы
php bin/setup.php --write-config  # создать config.php из переменных окружения
php bin/setup.php               # применить схему и создать администратора
php bin/setup.php --list-admins # показать логины администраторов
```

**Забыли пароль от админки.** Узнать его нельзя — в базе хранится только хеш.
Зато можно задать новый:

```bash
php bin/setup.php --list-admins                      # посмотреть, какие есть логины
ADMIN_USER=admin ADMIN_PASS='новый_пароль' php bin/setup.php --reset-password
```

Пароли передавайте через переменные окружения, а не аргументами командной строки:
аргументы видны другим пользователям сервера в списке процессов.

**Если что-то не сохраняется после обновления файлов.** Это значит, что структура базы
осталась старой. В админке появится жёлтая плашка с кнопкой «Обновить базу» — нажмите её
(или выполните `./deploy/update.sh`). До обновления источники не сохраняются и импорт
не запускается, чтобы не потерять данные.

**Обновление структуры базы.** Новые версии могут менять таблицы. Изменения лежат
в `db/migrations` и применяются сами при запуске `./deploy/update.sh` или
`php bin/setup.php` — по одному разу, порядок и факт применения хранятся в таблице
`schema_migrations`. На чистой установке миграции не выполняются: `db/schema.sql`
уже содержит актуальную структуру, они просто отмечаются как применённые.
Товары при этом не трогаются — новые поля заполнятся при следующем импорте.

### Что нужно сделать в панели Plesk

**1. Корень документов.** Хостинг и DNS → Параметры хостинга → Корневой каталог
документов:

```
/stocks/public
```

Это главный шаг для безопасности: наружу смотрит только папка `public`,
а `config.php`, загруженные прайсы и код приложения недоступны из интернета.
Если сменить корень документов нельзя, оставьте корнем папку проекта — в комплекте
есть `.htaccess`, который перенаправит запросы в `public/` и закроет служебные каталоги
(проверено на Apache 2.4: витрина и админка открываются, `app/`, `db/`, `bin/`, `deploy/`,
`storage/` и `config.php` отдают 403).

**2. Расписание импорта.** Инструменты и настройки → Запланированные задачи →
Добавить задачу. Точную команду с вашими путями печатает `install.sh`, обычно это:

```
Тип задачи:  Запустить команду
Команда:     /opt/plesk/php/8.2/bin/php /var/www/vhosts/ВАШ_ДОМЕН/stocks/bin/import.php --due --quiet
Расписание:  каждый час
```

Либо тип «Получить URL» с адресом `https://ВАШ_ДОМЕН/api/cron.php?token=ВАШ_CRON_TOKEN`.

Задача запускается раз в час, а импортируются только те источники, у которых
включён автоимпорт и прошёл их собственный интервал обновления.

После этого откройте `https://ВАШ_ДОМЕН/admin/` и войдите под созданным логином.

### Адреса сервиса

Зависят от того, куда указывает корень документов сайта. Оба варианта рабочие.

**Корень документов — `/stocks/public`** (рекомендуемый):

```
витрина    https://ВАШ_ДОМЕН/
админка    https://ВАШ_ДОМЕН/admin/index.php
установка  https://ВАШ_ДОМЕН/install.php
cron       https://ВАШ_ДОМЕН/api/cron.php?token=ТОКЕН
```

**Корень документов не меняли** — проект открывается как подпапка:

```
витрина    https://ВАШ_ДОМЕН/stocks/public/index.php
админка    https://ВАШ_ДОМЕН/stocks/public/admin/index.php
установка  https://ВАШ_ДОМЕН/stocks/public/install.php
cron       https://ВАШ_ДОМЕН/stocks/public/api/cron.php?token=ТОКЕН
```

Короткий адрес `https://ВАШ_ДОМЕН/stocks/` тоже ведёт на витрину: в корне проекта
лежит `index.php`, который перенаправляет в `public/`. Это работает и там, где
`.htaccess` не применяется (например, на nginx).

Все ссылки внутри сервиса относительные и указывают на файлы, а не на каталоги,
поэтому работают в любом из вариантов, даже если на хостинге не настроен
индексный файл каталога.

### Установка вручную (без SSH)

Если доступа к SSH нет, всё то же делается через Менеджер файлов Plesk:

1. Загрузите файлы проекта в каталог сайта.
2. Скопируйте `config.sample.php` в `config.php` и впишите доступы к базе,
   `site_name` и `cron_token` (любая случайная строка от 16 символов).
3. Выставьте права **775** на папку `storage` и вложенные `uploads`, `tmp`, `logs`.
4. Укажите корень документов `/stocks/public` (см. выше).
5. Откройте `https://ВАШ_ДОМЕН/install.php`, задайте логин и пароль администратора.
6. **Удалите файл `public/install.php`.**

## Окно «Поставщики»

Кнопка **«?»** в шапке рядом с «Заказами» открывает окно со списком поставщиков:
название, количество товаров и дата обновления прайса. Внизу — общая строка
«Каталог обновлён» с самой свежей из этих дат.

Дата берётся от **последнего успешного импорта**: если очередная загрузка
сорвалась, в окне останется дата тех данных, которые сейчас показаны в каталоге,
а не время неудачной попытки. Ошибки импорта видны в админке, в журнале.

Окно закрывается крестиком, кликом по затемнению и клавишей Esc.

## Раздел «Заказы»

У каждого товара в каталоге есть кнопка **«+»** — она кладёт товар в список
(повторное нажатие убирает, добавленные помечены галочкой). В шапке рядом с
названием магазина — ссылка «Заказы» со счётчиком.

На странице заказов позиции собраны **по поставщикам**: каждая группа свёрнута,
раскрывается по клику. У позиции название идёт первой строкой во всю ширину, под ним —
наличие от поставщика и шаг количества («−» и «+», число можно ввести руками).
Артикул и цена в списке не показываются. Для каждой группы:

* **Скачать** — файл CSV (открывается в Excel) с двумя колонками: товар и количество;
  имя вида `zakaz_Anex-Kazakhstan_2026-09-17.csv`;
* **Очистить** — убрать список этого поставщика;
* крестик у строки — убрать одну позицию, «Очистить всё» — весь список.

Список хранится **в браузере покупателя**, поэтому вход и регистрация не нужны:
у каждого посетителя свой список, он переживает перезагрузку страницы и
синхронизируется между вкладками. Серверных заказов сервис не хранит.

## Ссылки на облачные таблицы

В поле «Ссылка на файл» можно вставить не только прямую ссылку на прайс, но и обычную
ссылку из облака — сервис сам превратит её в ссылку на файл.

| Откуда | Что вставлять | Что происходит |
|---|---|---|
| Google Таблицы | `https://docs.google.com/spreadsheets/d/ID/edit#gid=0` | подставляется выгрузка `export?format=xlsx` (или `csv` — по типу источника); для CSV берётся именно тот лист, который открыт в ссылке |
| Google Таблицы, «Опубликовать в интернете» | ссылка вида `/d/e/…/pub?output=csv` | используется как есть |
| Google Диск | `https://drive.google.com/file/d/ID/view` | подставляется прямое скачивание файла |
| Яндекс Документы | `https://docs.yandex.ru/docs/view?url=ya-disk-public://…&name=Остатки.xlsx` | из ссылки берётся публичный ключ, прямая ссылка запрашивается через API Яндекс Диска |
| Яндекс Диск | `https://disk.yandex.ru/d/…`, `/i/…`, `https://yadi.sk/…` | то же через API Яндекс Диска |
| Любой другой сайт | прямая ссылка на файл | скачивается как есть |

**Доступ.** Документ должен быть открыт по ссылке хотя бы на просмотр: в Google Таблицах
«Доступ — Все, у кого есть ссылка — Читатель», на Яндекс Диске — «Поделиться» и публичная
ссылка. Логин и пароль сервис не запрашивает и закрытые документы открыть не может.
Если доступ закрыт, импорт напишет об этом прямо, а не «не удалось прочитать файл».

**Тип источника.** Для Google Таблиц выбирайте Excel (тогда скачивается вся книга .xlsx
и номер листа берётся из настроек источника) либо CSV (тогда скачивается один лист).
Для Яндекс Диска тип должен совпадать с форматом файла, который там лежит.

### Проверка ссылки

Перед настройкой источника ссылку можно проверить одной командой — она покажет,
что за сервис распознан, скачается ли файл и какие в нём столбцы:

```bash
php bin/check-url.php "ССЫЛКА" --type=excel
```

Пример вывода:

```
Сервис: Яндекс Документы
Прямая ссылка на файл: https://downloader.disk.yandex.ru/disk/...
Имя файла: Остатки Москва.xlsx
Готово: 148.2 КБ, за 1.3 с

Первые строки файла:
  строка 1 — A: Артикул | B: Наименование | C: Цена | D: Остаток
  строка 2 — A: YA-1 | B: Коляска Anex | C: 349000 | D: 5

Столбцы для маппинга указывайте буквами из вывода выше.
```

**Ограничение.** Ссылка на папку не подойдёт — нужна ссылка на конкретный файл.
Если вставить папку, сервис так и скажет и перечислит, что в ней лежит.

## Где может лежать проект

Проверено на Apache 2.4 во всех четырёх вариантах — выбирайте любой.

**1. Каталог — это весь сайт (рекомендуется).** Проект в `/var/www/vhosts/ДОМЕН/stocks`,
в Plesk корень документов `/stocks/public`. Сайт открывается по адресу `https://ДОМЕН/`,
админка — `https://ДОМЕН/admin/`. Служебные файлы физически вне корня документов.

**2. Корень документов менять нельзя.** Проект в `/var/www/vhosts/ДОМЕН/stocks`,
корень документов остаётся `/stocks`. Работает штатный `.htaccess` из комплекта:
он перенаправляет запросы в `public/` и отдаёт 403 на `app/`, `db/`, `bin/`, `deploy/`,
`storage/` и `config.php`.

**3. Каталог в подпапке рядом с основным сайтом.** Основной сайт остаётся в `httpdocs`,
а каталог открывается по адресу `https://ДОМЕН/stocks/`. Проект держим вне `httpdocs`
и делаем ссылку на его `public`:

```bash
ln -s /var/www/vhosts/ДОМЕН/stocks/public /var/www/vhosts/ДОМЕН/httpdocs/stocks
```

**4. Проект целиком внутри httpdocs.** Например `httpdocs/stocks` — тогда каталог тоже
открывается по адресу `https://ДОМЕН/stocks/`, маршрутизацию и защиту служебных папок
берёт на себя `.htaccess` из комплекта. Вариант рабочий, но менее надёжный, чем ссылка:
защита держится только на `.htaccess`.

Ссылки внутри приложения относительные, поэтому подпапка в адресе ничего не ломает —
это тоже проверено.

## Если сайт работает на nginx

Правила из `.htaccess` для nginx не применяются, поэтому здесь особенно важно
указать корнем документов `/stocks/public` (вариант 1 выше) — тогда служебные файлы
просто не лежат в корне сайта и закрывать их не нужно.

Если корень документов остаётся на папке проекта (вариант 2), добавьте
в **Дополнительные директивы nginx**:

```nginx
location ~ ^/(app|db|bin|deploy|storage)/ { deny all; }
location = /config.php { deny all; }
```

Для подпапки (вариант 3, ссылка на `public`) добавьте к путям префикс:

```nginx
location ~ ^/stocks/(app|db|bin|deploy|storage)/ { deny all; }
location = /stocks/config.php { deny all; }
```

## Как настроить источник

1. **Источники → + Новый источник.**
2. Название поставщика (видно на витрине), тип файла и способ получения.
3. Загрузите файл или укажите ссылку. Для ссылки можно включить автоимпорт и интервал.
4. Маппинг полей:
   * Excel/CSV — буква или номер столбца: `A` или `1`. Поле «Пропустить строк сверху» —
     обычно `1` (шапка таблицы).
   * YML — имена тегов: `name`, `vendorCode`, `price`, `count`, `picture`.
     Для атрибута оффера — `@available` или `@id`.
5. **Проверить маппинг** — покажет первые строки файла с буквами и номерами столбцов
   и результат разбора. Удобно сверять, не запуская полный импорт.
6. **Сохранить и импортировать.**

### Как показывается наличие

На витрине выводится **значение из прайса как есть**, без переписывания своими словами:
у одного поставщика «Есть в наличии», у другого «Более 5», у третьего «3».

Если колонка остатка в маппинге не указана, наличие не показывается вовсе.

Признак «в наличии / нет в наличии» по-прежнему вычисляется при импорте и хранится
в базе, но в интерфейсе витрины не используется — ни фильтра, ни сортировки по нему
нет. Он доступен только через API: `api/products.php?availability[]=in_stock`.

### Как показывается цена

Так же, как наличие — **ровно как записано в прайсе**: «9 736,50», «24 990 руб.»,
«от 1 490 ₽», «договорная». Разделители, знаки после запятой и приписки поставщика
сохраняются, ничего не пересчитывается и не округляется.

Параллельно из записи вынимается число — оно нужно только сортировке по цене.
У «договорной» числа нет, такие товары уходят в конец сортировки по цене,
но из каталога не пропадают.

### Скрытые строки и столбцы

Поставщики часто не удаляют снятые позиции, а просто прячут строки в книге —
и старые колонки прячут так же. В настройках источника Excel есть галочка
**«Не импортировать скрытые строки и столбцы»** (включена по умолчанию):

* скрытые строки не попадают в каталог;
* скрытые столбцы читаются как пустые — **буквы столбцов при этом не сдвигаются**,
  поэтому маппинг менять не нужно;
* в журнале импорта видно, сколько скрытого пропущено: «Пропущено скрытого
  в книге — строк: 2, столбцов: 1».

Работает для обоих форматов Excel, `.xlsx` и `.xls`. Для CSV и YML настройки нет:
в этих форматах скрытых строк не бывает. Если снять галочку, книга читается целиком,
как раньше.

### Валюта

Обозначение валюты дописывается к цене, только если в самой записи его ещё нет:
«9736» → «9736 ₽», а «24 990 руб.» остаётся без изменений.

Валюта берётся по порядку: из файла (если столбец или тег указан в маппинге) →
из настроек источника → `default_currency` из `config.php`. Известные обозначения
приводятся к коду (`руб` → `RUB`, `тг` → `KZT`), незнакомое сохраняется как есть.

### Что происходит при повторном импорте

Товары сопоставляются по паре «источник + артикул»: существующие обновляются,
новые добавляются, а пропавшие из прайса — удаляются. Если импорт завершился
ошибкой, старые товары остаются на витрине нетронутыми.

## Расписание обновления

Задача в планировщике (раз в час) запускает `bin/import.php --due` или
`api/cron.php?token=…`. Обновляются только источники, у которых включён автоимпорт,
указана ссылка и прошёл их собственный интервал.

**Запас в 5 минут.** Планировщик запускается по своим часам: между ежечасными
запусками проходит 59 минут 59 секунд. Без запаса источник с интервалом 60 минут
пропускался бы через раз — обновлялся бы раз в два часа, а при суточном интервале
и ежедневной задаче — через день. Поэтому источник считается готовым к обновлению
за пять минут до формального срока.

**Видно, работает ли планировщик.** Каждое обращение отмечается в
`storage/scheduler.json`, и на странице источников появляется строка состояния:

* «Планировщик ни разу не обращался к сервису» — задача в Plesk не настроена;
  тут же выводятся готовая команда и ссылка с вашим токеном;
* «Планировщик молчит N часов» — задача есть, но не отрабатывает;
* «Планировщик работает: последний запуск 5 минут назад» — всё в порядке.

Рядом с каждым источником в списке видно, когда он обновится в следующий раз.

**Часовой пояс.** Расписание и даты считаются по часовому поясу из `config.php`:

```php
'timezone' => 'Asia/Almaty',
```

Приложение задаёт этот же пояс сессии MySQL, поэтому время в базе и в интерфейсе
совпадает. Если часы в админке показывают не ваше местное время — поправьте эту
строку и обновите страницу.

### Импорт из командной строки

```bash
php bin/import.php --due            # только те, у кого подошло время (для cron)
php bin/import.php --all            # все активные источники
php bin/import.php --source=3       # конкретный источник
php bin/import.php --due --quiet    # без вывода в консоль
```

Код возврата: `0` — успех, `2` — часть источников с ошибкой, `1` — критическая ошибка.

## Производительность

Замеры на тестовом стенде (PHP 8.4, MariaDB 10.11):

| Операция | Результат |
|---|---|
| Импорт CSV, 20 000 строк | 1,4 с, пик памяти 4 МБ |
| Повторный импорт тех же 20 000 строк | 1,9 с |
| Импорт Excel (.xlsx), 5 000 строк | 0,6 с, пик памяти 8 МБ |
| Поиск по каталогу из 25 000 товаров | ~110 мс |

Файлы читаются потоково, товары пишутся пакетами по 300 строк, поэтому память
не зависит от размера прайса. Поиск работает через `LIKE '%…%'` — это даёт
подстроку в любом месте названия и артикула; на каталогах свыше нескольких сотен
тысяч товаров имеет смысл перейти на полнотекстовый индекс.

## Обновление стилей в браузере

Ссылки на CSS и JS содержат версию по времени изменения файла
(`assets/css/catalog.css?v=1789638404`), поэтому после `git pull` браузер
сам забирает свежие стили. Раньше версия была постоянной, а сервер просил
кэшировать статику на неделю — у кого файл успел закэшироваться, тот видел
новую разметку со старыми стилями: разъезжались колонки списка и кнопки.

Если вёрстка всё же выглядит странно, обновите страницу с очисткой кэша
(Ctrl+F5, на Mac ⌘+Shift+R) — один раз.

## Решение проблем

**«Сервис не настроен»** — нет файла `config.php`, скопируйте его из `config.sample.php`.

**«Нет прав на запись в storage/…»** — выставьте права 775 на `storage` и вложенные папки.

**«Из файла не удалось импортировать ни одного товара»** — скорее всего перепутаны столбцы
или число пропускаемых строк. Откройте «Проверить маппинг»: там видно, какие данные
в каком столбце лежат.

**Файл больше лимита загрузки** — увеличьте `upload_max_filesize` и `post_max_size`
в **Параметрах PHP** Plesk либо используйте загрузку по ссылке.

**Импорт большого прайса обрывается** — увеличьте `max_execution_time` и `memory_limit`,
либо запускайте импорт из планировщика: CLI-версия не ограничена временем выполнения.

**Кракозябры вместо русских букв в CSV** — укажите кодировку явно (Windows-1251)
в настройках источника вместо автоопределения.
